# GlintWin v0.4.2

## 输入初始定位
首个OCR坐标不再立即采用。初始定位及布局大幅变化需要两次间隔60–400ms的相符采样；未显示时以80ms间隔尝试采样，并强制重新OCR，不能用旧识别结果代替第二帧。常态仍按250ms采样，保留小抖动死区和真实窗口移动跟随。确认额外耗时受系统OCR速度影响，不保证固定显示延迟。

生产端记录输入轮次：隐藏事件即使被有界队列丢弃，新一轮输入仍清除旧定位和遮挡缓存。OCR返回时检查窗口版本与输入修订号，过期结果不显示；不可信离群坐标不能延长旧锚点寿命。

位置状态机19项回归覆盖异常首帧、间隔不足、首次坐标变化、过期重新确认、连续离群点、真实窗口平移及丢隐藏事件。自动化验证不等于已覆盖所有输入法皮肤和DPI组合，实际初始输入体验仍需在用户当前环境观察。

## 两个新词包
- `modern_daily.json`：60条日常口语与网络表达，例如“稍等一下”“发我一下”“情绪内耗”。
- `modern_tech.json`：95条AI、编程与办公术语，例如“检索增强生成”“上下文工程”“代码审查”“数据透视表”。

以上155条为本项目整理的简短英文释义，拼音采用无声调格式，与现有拼音匹配兼容。相对基础词典及旧3包，新增133个独立词头、补充/覆盖22条释义，总覆盖121645→121778（不含用户自定义词库）。这是一批针对性补充，不代表已完成大型通用词库扩容。源词条均有数量、拼音音节数及加载后释义一致性检查。

词库管理页现在自动发现 `Data/Packs/*.json`，显示条数并提供启停开关和“打开词包目录”；新词包无需修改UI代码。新安装默认启用5包，既有配置保留原开关，新包可自行开启；本次为用户选择的两个方向启用新包。

## 持续扩库方案
1. 优先使用每日词汇的高频待译词，经人工核对后加入自定义词库，避免OCR误字污染主词库；自动采集仍由用户自行开启。
2. 个人/团队常用词通过CSV导入；可分发的领域词库使用JSON词包，复制后重新进入词库页即可启用。
3. 基础库使用[CC-CEDICT官方发布](https://www.mdbg.net/chinese/dictionary?page=cc-cedict)。当前转换脚本优先使用本地缓存，基础库更新应先保存旧版、下载新发布、比较实际新增与释义变化后再替换，不盲目叠加重复词库。
4. 长句通常不能靠增加词头解决；若未来引入离线翻译模型，应作为独立可选模块评估准确率、内存和延迟。
