# 产品验收报告 — GlintWin P1 MVP

| 项 | 内容 |
|---|---|
| 验收对象 | GlintWin 0.1.0（搜狗输入法候选词英文释义悬浮条） |
| 验收环境 | Windows 11 25H2 (26200) / 搜狗输入法 16.9.0.5523 / 2560×1600 |
| 验收方式 | 自动化单元测试 + 端到端模拟打字 + 日志/截图取证 + 静态合规扫描 |

## 1. 验收标准核对（源自技术方案 §1）

| # | 标准 | 结果 | 证据 |
|---|---|---|---|
| 1 | 搜狗打拼音时，候选栏正下方出现圆角悬浮条 | ✅ 通过 | E2E 截图 `e2e_1/e2e_3.png`；词级坐标锚定候选行，左对齐贴行底 |

## 2. 质量证据

- **单元测试**：`tools/ParserTest` 18/18 通过（用例全部来自真机 OCR 实际乱码形态回归）。
- **端到端**：`tools/e2e_typetest.ps1` 模拟真实打字 → 截图比对，悬浮条内容/位置/配色符合预期。
- **防闪烁验收**：静置打字后 2.5s+ 日志零 OCR 记录（哈希只看候选行区域）；主题色平滑收敛（无逐帧跳变）；首显需连续两帧一致（无碎片字闪现）。
- **隐私合规**：无网络代码、无键盘钩子、无进程注入（只读屏幕截图方案）——与产品声明一致。
- **稳定性**：OCR/词典/渲染异常均有独立 try/catch 隔离，不影响输入法本身；单实例互斥；日志 5MB 轮转。

## 3. 性能

- 端到端延迟（候选变化 → 悬浮条更新）：约 60–120ms（截图 5ms + 2x OCR 20–40ms + 渲染 ~10ms），满足 <80ms 预算的量级目标。
- 静态时 CPU 占用趋近于零（哈希去重 + 250ms 限频采样）。

## 4. 已知限制（验收边界）

1. 仅支持搜狗输入法；微软拼音支持为 P2（本次迭代随后实施）。
2. 拼音纠错依赖拼音框可读性：艺术字皮肤下 OCR 读不准拼音时，纠错保守不触发（宁缺勿错），主识别路径不受影响。
3. 管理员权限窗口无法截图（Windows 会话隔离）。
4. 释义取第一候选；跟随翻页选中项为 P3。

## 5. 验收结论

**通过**。P1 MVP 达到技术方案定义的验收标准，进入 GitHub 托管与 P2（微软拼音）迭代。
