# Stable overlay and daily vocabulary design
User approved the previous daily collection flow and now requests implementation, default-off automatic daily collection, position stability and verification of exe distribution. Keep existing WPF and offline OCR. Do not collect raw keystrokes, screenshots, application text, or mouse-only guesses. OCR with an explicit space/number selection is still inferred, marked NeedsReview until user approves. Cancellation, stale snapshots, changing foreground, changed spelling, disabled/paused collection must not persist. Numeric choices may be skipped unless mapped reliably. Collection pipeline writes through a bounded asynchronous queue to local SQLite under LocalApplicationData; query only one date/page. Daily UI supports toggle, pause via existing tray pause, process exclusions, date/status/search, counts, editing translation, confirming, ignoring, export, adding to custom dictionary, delete date with in-app confirmation. Store collection disabled by default. Package built-in Data as embedded assets extracted only when absent to writable per-user folder; app remains self-contained win-x64 and requires Windows OCR Chinese language capability. Preserve existing user custom files/config. Position uses window-local stable row offsets, hysteresis and new-session reset; no fallback jumping after a known row, valid rows only, preserve follow on genuine window movement, source switch reset.
